## 已确认范围

用户要求完善请求记录、持久化起止时间和详情，并将失败异常分开；随后明确选择“只保存元数据”。正文保存方案未被采用。记录保存在现有本地 SQLite 中，外部客户端不能读取或管理这些记录。代码修改不等于当前运行的旧版已经更新。

“请求记录”显示全部经过网关入口的请求，包括运行中、完成、受限结束、失败、取消和中断；“失败异常”单独显示关联请求 ID、异常时间、阶段、固定错误码及网关生成的安全原因。包括鉴权、参数、并发、上游、断流、超时及取消异常。HTTP 已返回 200 的 SSE 仍可能失败，以最终结果及异常码判断。

2026-10-14 双主题页面重构将详情移入右侧抽屉，新增观察时间线与本页元数据搜索。搜索不跨分页，未加载关联请求时不推断模型或客户端。时间线只显示实际记录字段；恢复确认不是真实结束，缺少首个输出仍为未知。复制明细按面板顺序包含时间线、流失败提示及完整诊断字段；展示与复制共用记录快照。页面代码尚未编译或运行，待验见 [重构清单](../04-quality/desktop-redesign-checklist.md)。

2026-10-13 用户要求将详情中的“复制 ID”改为“复制明细”。请求与失败异常共用的详情面板现提供该按钮，复制标题及面板显示的全部诊断字段；当前异常分页已加载对应记录时，详情同时展示并复制异常代码、原因、时间、阶段和异常 HTTP 状态。展示与复制使用同一份文本快照，点击后状态栏提示“请求明细已复制”。仅复制已有元数据和网关安全原因，不读取或补采请求正文、Token 或密钥原值。

## 字段和时间含义

页面纠偏后，异常列表使用紧凑结果标签，错误码和安全原因在详情中查看。关联请求不在当前页时，模型/客户端写明“见明细”，不猜测。右侧先显示时间线、HTTP/用量摘要；“查看完整诊断字段”展开其余字段，复制明细始终导出当前快照的完整元数据。该界面变更尚未运行验证。

| 字段 | 含义 |
|---|---|
| 请求 ID | 与客户端响应的 x-request-id 一致，可复制关联排障 |
| 方法、接口、模型 | 固定接口名称及受约束的模型标识；未知接口只记 unknown，不保存原始 URL 或查询字符串 |
| 密钥/账号 ID | 用于区分调用来源；不保存密钥原值或 OAuth 凭据，不随密钥撤销删除历史记录 |
| 流式、请求字节数、消息/输入项数、工具定义数 | 解析后的结构元数据；未读取或无法确定的值显示未提供 |
| 开始时间 | 请求到达网关入口时记录；UTC 毫秒保存，界面显示本地时间 |
| 结束时间、耗时 | 网关处理及发送队列结束时的时间；运行中无结束时间，耗时使用单调时钟；不代表客户端已经消费完所有字节 |
| 首批上游数据、首个输出 | 分别观察上游字节及非空文本/函数参数/拒绝增量；前者可能只是创建事件或心跳；不是准确 token 时间 |
| 最近上游活动 | 最近读取到上游字节的时间，不由本地 UI 刷新或下游发送更新 |
| HTTP 状态、上游 HTTP | 入口返回状态及已经取得的上游成功响应状态；未取得响应时上游状态为未知，不推断 |
| 输入/输出 tokens | 上游终态提供的用量；缺少时保持未知，不填零 |
| 缓存输入 tokens | 0009起保存上游实际提供的缓存输入数，属于输入 Token 的子集；详情和复制完整字段可查。旧记录、缺失/负值/非整数为未提供，不回填0；概览命中率及有效样本口径见[首页统计](../02-design/overview-statistics.md) |
| 中断恢复 | 无法确定崩溃瞬间，显示“恢复确认时间”；耗时保留最近持久化观察值，不包含应用关闭期间的时间 |

旧版本的 413 表示请求体超过当时的 2 MiB 限制，入口即拒绝，尚未调用生成上游；历史记录可能仍保留合并原因及“未提供”的请求大小。2026-10-13 用户随后要求取消请求体大小上限，新代码不再因超过 2 MiB 产生本地 413。读取成功后按实际字节数记元数据；JSON 无效仍返回 400，Content-Type 错误仍返回 415，新原因文案为“请求正文读取失败、JSON 无效或 Content-Type 不正确”。不改写历史异常。

## 参数校验失败怎么处理（2026-10-14）

用户先要求通用 400 原因具体，再明确要求放松校验、默认信任下游字段。当前不再因未知字段、temperature、长度参数类型、reasoning_content 类型/角色、工具索引/名称元数据或历史配对产生本地 400。转换用不到的字段跳过，原生可映射值由上游判断，权威规则见 [默认信任契约](../03-architecture/api-contracts.md#默认信任下游字段2026-10-14)。

当结束阶段为“校验参数”、HTTP 为 400 且无上游 HTTP 时，查看转换所需的基本结构。安全原因现在指出例如 `model` 必须是非空字符串、`messages` 必须是数组、`messages[0].tool_calls[0].id` 缺少调用 ID，或内联图片 URL 无法转换。路径与固定建议同时展示和复制，不回显值。上游不接受已转发的原生值属于上游失败阶段。

旧记录只保存通用原因，无法从请求体大小或数量推断原字段。旧原因保持，不补采正文或任意字段名；更新程序后重新请求可能正常完成，或得到必需结构/真实上游错误。

详情按请求 ID 独立读取关联异常，不依赖当前异常分页；切换/收起详情后不接受旧请求的延迟响应。小于 10 毫秒的耗时/延迟使用毫秒显示，避免 5 毫秒舍入为 0.00 秒。界面与复制采用同一文本。

本次仍未编译、运行测试、更新 EXE 或真实客户端联调，验证命令见 [测试清单](../04-quality/request-records-checklist.md)。

请求开始即写入；运行中最多每秒写一次快照；结束结果与关联异常在同一事务提交。检查点不能重新打开已结束请求。写入失败会计数并在本次监听的界面告警，不以写入失败伪造推理成功。崩溃可能丢失最近一秒左右的进度；启动将未结束记录恢复为中断。

每分钟清理超过 7 天或最近 10,000 条之外的已结束记录，关联异常一并移除；运行中的记录不清理。清理不是安全擦除。分页每页 100 条，执行中的请求置顶，停止监听后仍能查看历史。

## 长时间请求怎么判断

1. “读取客户端请求”：客户端可能尚未发送完整正文。
2. “等待上游”：包含凭据检查/续期、模型目录查询和等待生成响应头；此时尚未读取生成数据，不能仅凭耗时断言模型卡住。
3. “接收上游”：结合首个输出及最近上游活动判断是否有新数据；有上游活动但无可见输出可能是心跳或推理，不能据此确认正常或失败。
4. “发送给客户端”：正在向有界发送队列写入，持续等待可能是客户端读取缓慢。
5. “失败异常”：查看 upstream_timeout、slow_consumer、upstream_stream_interrupted、upstream_failed、request_cancelled 或 client_disconnected 等原因，再打开关联详情。

当前代码沿用上游空闲 90 秒、慢消费者 30 秒和 reqwest 生成 HTTP 请求 300 秒总超时；凭据和目录查询另有各自限制，不能把 300 秒解释为整个网关生命周期的统一上限。上游有效 completed/incomplete 终态校验通过后结束，不继续等待 TCP/HTTP 流关闭。没有可信终态的 EOF 仍为异常，失败事件不发送成功 [DONE]。

## 流中断诊断（2026-10-15）

`upstream_stream_interrupted` 之前将网络读取、SSE/JSON 解析、事件身份/顺序/字段校验和缺失终态等分支合并为固定原因。2026-10-15 用户提供的失败记录已通过只读数据库查询核对：上游 HTTP 200，首批数据之后约 29.74 秒失败，无已记录的可见输出或 usage；相似历史记录也在首批数据约 30 秒后失败。这只是时间特征，不能据此断言本地超时、上游故障或工具参数错误。现有历史记录没有保存具体分支，无法恢复真实原因。

源码现保留错误码，细分安全原因：网络/传输读取错误、SSE 单事件超限、无效 UTF-8、未完整接收的事件、无效 JSON、event/type 冲突、提前/重复哨兵、终态之后的事件、未支持/缺失类型的事件、工具/输出条目校验、completed/incomplete 校验，以及无有效终态的 EOF。分类只使用本地固定文案，不保存原始事件名、解析器错误、正文或工具参数；“未支持事件”不输出上游给出的任意类型名称。

流式 SSE 和聚合 JSON 共用安全原因生成及持久化。流式已提交 HTTP 200 时，具体原因放入流内 error，同时写入关联异常；异常 HTTP 为 502，不伪造成功终态或 `[DONE]`。旧记录保持原原因，不新增迁移。部分校验仍按事件类别归纳，不能凭类别断言某个具体字段错误。

本次先补 11 类失败 × 两接口 × JSON/SSE 的回归代码，再修改实现；按项目约定未执行编译型测试、构建、真实上游调用或更新运行中的 EXE。仅源码交付，待验命令见[请求记录清单](../04-quality/request-records-checklist.md)。本次没有改变本地超时、重试或成功判定。

## 隐私与历史边界

不持久化请求/响应正文、聊天、代码、工具参数、图片、认证头、Token、密钥或上游原始报错。错误详情使用代码生成的必要字段路径、数组索引及固定规则/建议；未知字段默认接收，不以任意名称生成异常，避免将未知参数名和上游正文带入异常表。元数据是 SQLite 普通字段，并非全库加密。

旧版本只有内存中的完成请求元数据，无法补回没有保存的历史详情。新代码需由用户明确选择验证和运行后生效；此次未修改真实数据目录，也未替换现有程序。
