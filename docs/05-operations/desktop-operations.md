# 桌面运行、客户端接入与恢复

状态：Review  
最后更新：2026-10-14  
关联文档：[桌面流程](../02-design/desktop-flows.md)、[API 契约](../03-architecture/api-contracts.md)、[威胁模型](../03-architecture/threat-model.md)

本文包含目标行为与当前开发版操作；尚无安装包，实际交付以 [验证记录](../06-delivery/implementation-status.md) 为准。

## 安装与启动

首发建议 Windows x64，最低系统版本在 P0 确定。安装包处理所需原生运行资源，用户不需要 Rust、Node、Java、Codex 或数据库服务。

正常权限运行。应用启动后默认自动启动代理，开机自启尚未实现。只在本人登录会话中运行，不作为 Windows Service。

启动时发现数据库版本过新、迁移失败或凭据无法解密，显示明确恢复信息，不覆盖旧数据或创建空配置伪装正常启动。

### 代理自动启动

2026-10-13 用户要求打开项目时同时启动代理，替代此前每次手动开启监听的默认行为。后台先恢复本地数据，再检查已有登录账号及至少一个未撤销的客户端密钥；齐备后自动启动网关。首次尚未配置时正常打开应用并提示登录或创建密钥，配置完成后首次手动启动即可。

每次成功启动保存具体监听地址，下次打开应用恢复该地址；首次或旧版本没有保存过地址时使用 `127.0.0.1:8787`。客户端接入页回填保存值。修改地址需先停止网关，输入新地址后启动；失败的尝试不覆盖上次成功值。

自动和手动启动使用相同的账号、密钥和地址校验。端口占用、地址不存在或保存失败时显示错误，应用仍可操作；不会改端口、换网卡或降级为通配监听，可修改后手动重试。自动启动本身不执行模型测试或生成请求；既有只读额度调度不变。

手动停止保持到本次应用退出，不被定时任务再次启动；下次打开应用仍自动启动代理。Windows 关闭窗口默认收起托盘并继续运行；主动退出才停止监听及后台任务。此行为不等同于 Windows 开机自启。

### 自定义端口（2026-10-14）

用户要求端口可自定义以避开占用，因此将客户端接入页原来的 `IP:端口` 单一输入拆为“监听 IP”和“端口”，继续使用原有成功监听配置的保存与恢复规则，不新增数据库迁移。当前为源码交付，尚未编译或运行；测试及实机步骤见 [自定义端口清单](../04-quality/custom-port-checklist.md)。

在“客户端接入 → 连接地址”操作：服务运行中先点击“停止服务”，保留原 IP，仅把端口改为可用的值（例如 `8877`），再点击“启动服务”。端口范围为 1–65535；IP 留空使用 `127.0.0.1`，端口留空使用 `8787`。非法端口显示范围错误，不发起监听。

启动成功后刷新 Base URL、Chat Completions 和 Responses 完整地址，客户端需要更新到新地址。新配置只在监听及保存成功后持久化；应用重开回填原 IP 与自定义端口，并按既有条件自动启动。服务运行及启停等待期间输入禁用，运行时显示停止后可修改的提示。

占用错误显示具体端口及上述修改入口，原端口仍被占用时也可改用其他端口启动；失败尝试保留输入供修改，不覆盖上次成功配置。系统未报告端口占用的其他监听错误继续显示真实原因。

## Windows 窗口与托盘

2026-10-14 根据用户要求修改源码，尚未重新构建、打包或实机验证；已发布 v1.0.0 和现有 EXE 不会自动获得这些变化。验证范围见 [桌面生命周期清单](../04-quality/desktop-lifecycle-checklist.md)。

- 桌面 EXE 使用 Windows GUI 子系统，双击启动不附带控制台窗口，启动错误改为原生错误对话框。
- 右上角关闭及 Alt+F4 隐藏主窗口并保留后台服务；每次运行首次收起尝试显示系统提示，Windows 通知设置可能抑制提示。图标可能位于任务栏的隐藏图标区。
- 点击或键盘激活托盘图标恢复主窗口；右键菜单提供“显示 Tiny Proxy”和“退出 Tiny Proxy”。再次打开同一数据目录的 EXE 恢复现有实例。
- 托盘退出和设置中的“退出应用”才结束进程，沿用后台停监听、取消请求及数据库收尾流程。确认在线更新后的安装重启仍真正退出。
- 托盘创建或恢复失败保留/恢复主窗口，并提供设置退出入口；Explorer 重启后尝试重建图标。

本次只实现 Windows 托盘，macOS 仍关闭窗口即退出；未增加关闭行为设置或开机自启。

## 本机与其他设备

本机建议 http://127.0.0.1:8787/v1。其他设备使用桌面接入页展示的具体 LAN/VPN 地址，不能填写 127.0.0.1 或 0.0.0.0。

个人 VPN 地址优先用于跨网络设备。应用不配置 VPN、不建立 NAT 穿透；源设备能否到达目标地址由路由和防火墙决定。普通 LAN HTTP 不加密内容，界面须明确；不可信网络使用个人 VPN。

绑定具体地址后，IPv4 变化需要更新客户端配置；地址不存在时服务报错，不自动扩大监听范围。

## Trae 接入

按当时客户端实际界面验证以下步骤：

1. 添加自定义模型，格式选择 OpenAI Chat Completions。
2. Base URL 使用桌面生成值；也可启用完整 URL，填写其完整 /v1/chat/completions 地址，避免重复拼接 /v1。
3. API 密钥填写本应用创建的网关密钥，模型 ID 从模型页复制。
4. 高级采样/输出字段只设置已支持选项；客户端预设可能自动加字段，需按兼容记录使用经过测试的配置。
5. 先测试文本，再用专门测试目录完成一次客户端工具调用往返。
6. 在第二台设备重复；桌面请求列表应显示对应密钥名称。

以上依据 [Trae 官方配置说明](https://docs.trae.cn/ide_models)。实际版本和兼容配置在 P3 形成记录，不承诺任意版本默认配置都可用。

## 常见问题

### 安装版提示本地数据库初始化失败

2026-10-14 已通过只读核对发现：Windows v1.0.0 安装版内嵌 CRLF 迁移脚本，而已有开发数据库保存 LF 脚本校验值，两者触发 SQLx 迁移校验冲突。旧提示将所有初始化错误都归为目录权限，因此不能只根据该提示修改权限或删除数据库。

源码现已固定迁移文件 LF，并兼容仅换行不同的历史校验值，不改写已有迁移记录。其他 SQL 内容差异、未知版本和未完成迁移仍拒绝打开。错误提示已区分迁移冲突与文件访问等原因，并显示数据库路径；不显示原始 SQL 错误内容。

此修改尚未运行测试、构建或更新安装版；已有 EXE 仍使用原逻辑。请保留原库，不要删除 `app.db` 或手工修改 `_sqlx_migrations`。证据、回归命令与安装版待验场景见 [数据库启动兼容清单](../04-quality/database-startup-checklist.md)。

| 表现 | 检查顺序 |
|---|---|
| 连接拒绝 | 应用是否运行、服务是否监听、IP/端口、网卡/VPN、防火墙 |
| 401 invalid_gateway_key | 网关密钥是否完整或已被撤销删除；重新创建或使用有效网关密钥 |
| 403 key_revoked | 新建密钥并更新该客户端 |
| 503 upstream_auth_required | 在桌面检查账号连接并重新登录 |
| 400 unsupported_parameter | 客户端实际字段与 API 支持表，不要静默删参重试 |
| 429 | 区分本网关并发与上游额度；按错误码恢复 |
| 有文字但请求失败 | 查看流内错误或终态缺失，不能以已有文字判定完成 |
| 模型不见了 | 活动账号、目录刷新和真实权限，不手工伪造模型 |
| 窗口关闭后失联 | 检查是否主动退出、托盘是否可用、系统是否休眠 |

## 停止、退出与更新

停止服务先拒绝新请求，再在规定时间内等待/取消；UI 显示剩余请求数。主动退出同样释放端口与任务。关闭窗口是否留在托盘按设置执行。

首版采用手动安装更新，不自动下载、替换或重启。更新前检查 schema 兼容并做一致性备份；旧版不强行打开新版数据库。

## 数据与诊断

### 数据目录统一与历史恢复

2026-10-13 起，默认数据库为 `%USERPROFILE%/.tiny-proxy/app.db`，`cargo run` 与直接运行 exe 使用同一目录。`TINY_PROXY_DATA_DIR` 仍可显式指定隔离目录；设置该变量时不自动导入其他目录的数据，空值报错。

旧默认路径 `%LOCALAPPDATA%/TinyProxy/app.db` 可能被 MSIX 启动器映射到 `%LOCALAPPDATA%/Packages/<包标识>/LocalCache/Local/TinyProxy/app.db`。两次启动即使打印同一 AppData 字符串，也可能实际打开不同文件。排查必须核对文件句柄的最终物理路径；不要仅凭显示路径判断是同一库。Windows 行为依据：[Microsoft AppData 重定向说明](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes#appdata-operations-on-windows-10-version-1903-and-later)。

新默认数据库尚不存在时，后台检查普通旧目录和各包中对应的 TinyProxy 目录，解析实际路径并去重。仅当恰好一份旧库有账号、密钥或历史数据时恢复；空库不会盖过有数据的旧库。旧版仍运行、旧库损坏或多份旧库都有数据时，显示错误并停止，不创建空库伪装成功。已有目标库永不被旧库替换。

恢复持有新旧目录实例锁，以只读连接执行 SQLite `VACUUM INTO` 生成包含已提交 WAL 页的一致性副本，校验并刷新磁盘后以不覆盖方式发布；原库与备份继续保留。该机制依据 [SQLite VACUUM INTO](https://www.sqlite.org/lang_vacuum.html#vacuum_with_an_into_clause)。迁移中断产生的临时副本不作为正式 app.db 打开；再次启动重新恢复。后续以新目录为准，不再打开旧构建写入原目录。

控制台 `startup database=...` 显示所选路径，`local_state keys=... accounts=... models=... tests=... connected=...` 只报告加载数量；不记录密钥或 Token。读取失败不会再被“已就绪”覆盖。

数据目录由 UI 提供打开入口。日志/请求记录为元数据；诊断包不包含数据库、凭据或正文。记录清理按保留规则执行。

凭据受当前 Windows 用户环境保护，复制数据库到其他设备不保证解密；更换设备重新登录。恢复旧备份可能包含已失效轮换凭据，应检查连接并要求重新登录，不能覆盖当前有效会话。

若用户要求删除全部本地数据，先停止服务、退出会话并说明删除范围；最终清理动作必须另行明确确认，不因普通卸载自动删除账号数据。



## 已保存账号、模型、测试和密钥

账号页逐条显示已授权账号；添加同一身份会更新凭据，不覆盖其他账号。停止网关后可切换当前账号，模型页恢复该账号目录和最近 100 条文本测试历史。旧版未落库的模型/测试历史无法追溯，升级后重新读取/测试即保存。

客户端接入页的新密钥可反复查看、复制；展示两分钟后隐藏，之后仍可再查看。旧版只保存摘要的密钥无法恢复，原值仍有效，可自行新建替换；不会自动撤销。

2026-10-13 按用户要求改为撤销即删除，依据 [B20](../01-requirements/business-rules.md)：确认撤销成功后删除整条密钥记录，并移除列表行和当前显示的该密钥明文，重启后不再显示。新版本首次启动清理旧版已经撤销的密钥；有效密钥保留。旧值请求返回 401 invalid_gateway_key，原客户端需改用新密钥；撤销失败显示错误并保留原记录。

每个账号显示额度窗口剩余百分比、下次重置时间、可用重置次数及数据更新时间。手动点击“刷新额度”；应用运行时按上次尝试一小时后查询（调度扫描最多约一分钟延迟），重启补查到期账号，退出期间不运行服务。查询不消耗重置机会。失败保留旧快照并标出失败；上游没有提供的字段显示“未提供”，不能据此认定额度为零。

开发命令 `cargo run --locked --example check_models -- --refresh-usage --test-text` 会读取目录、只读查询额度并执行一次固定短文本测试，使用同一保存逻辑。`--test-text` 使用模型额度；输出仅数量/完成状态/安全错误，不输出凭据或正文。升级前使用 SQLite backup API 备份，不能只复制正在写入的主数据库文件；DPAPI 密文依赖原 Windows 用户，备份不等于跨设备可移植。
