# 用户故事地图

状态：Review  
最后更新：2026-10-13  
关联文档：[PRD](prd.md)、[开发计划](../06-delivery/development-plan.md)

| 用户活动 | MVP 故事 | 对应阶段 |
|---|---|---|
| 建立连接 | 首次打开看到登录入口；浏览器授权；回到应用看到已连接或可恢复错误 | P0、P2 |
| 确认能力 | 看到当前账号的模型；复制 ID；主动进行一次最小连接测试 | P2 |
| 开放服务 | 创建客户端密钥；选择网卡和端口；启动或停止监听 | P3、P5 |
| 接入 Agent | 复制 Base URL/完整接口地址；在 Trae 保存并完成文本请求 | P3 |
| 完成工具任务 | Agent 接到完整工具参数；在客户端执行；将结果送回；获得最终回答 | P3 |
| 使用 Responses | Responses 客户端使用完整 input 历史和原生事件继续对话 | P4 |
| 日常运行 | 收起托盘；查看并发和失败；恢复窗口；主动退出 | P5 |
| 排查问题 | 区分密钥错误、上游登录失效、限流、断流和网络不可达 | P3—P6 |
| 管理访问 | 按设备撤销密钥；切换本人连接；退出账号；清理本地记录 | P5—P6 |
| 更新安装 | 手动更新应用，保留可迁移配置，确认干净机可运行 | P6 |

## 最小纵向切片

第一条有效链路必须是“桌面登录 → 选模型 → 本机 Chat Completions 文本流”。第二条才是“客户端工具调用往返”；第三条是“第二台设备访问”。

Responses 原生兼容、桌面完整页面和安装收尾依次叠加。每一片都能演示并验收，不等待所有页面做完才验证登录或推理。
