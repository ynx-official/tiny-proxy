# 问题定义

状态：Review  
最后更新：2026-10-13  
关联文档：[章程](../00-project/project-charter.md)、[PRD](prd.md)

## 使用者与问题

唯一产品角色是本机所有者，也是其他设备与 Agent 的使用者。用户希望复用自己的模型访问能力，但各 Agent 接受的接口、登录方法与流式事件并不一致。

解决的问题：

1. 没有安装 Codex 时，仍能在桌面应用中建立自己的登录连接。
2. Agent 只需配置 API 地址、网关密钥、模型 ID，不接触上游凭据。
3. 上游 Responses 流能正确转换为客户端所需的 Chat Completions 流。
4. 用户能看清“是否登录”“能否推理”“服务是否监听”“某次请求为什么失败”。
5. 本机与其他个人设备均可接入，服务生命周期由桌面应用掌控。

## 系统边界

输入是其他 Agent 产生的模型请求；输出是模型回答或工具调用描述。工具运行、文件编辑、命令执行、审批和下一轮推理由外部 Agent 负责。

应用只转发每次模型推理，不连接客户端文件系统，不接管 Agent，不要求客户端信任根证书。

## 最大不确定性

- 目标账号能否通过拟选认证路线获得所需模型权限。
- Trae 实际发送的字段和工具协议能否被严格适配。
- GPUI 与 GPUI Kit 在目标 Windows、输入法、缩放、托盘和打包环境中的实际表现。

这些问题由 P0/P3 的实验回答，不能从“参考项目有代码”推导为“新项目已可用”。
