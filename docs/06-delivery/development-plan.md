## 当前状态与执行原则

2026-10-13 用户要求“开始实行”，已进入 P0，并创建用于验证的 Cargo 工程与必要本地基础模块。当前具体产物和检查证据见 [开发验证记录](implementation-status.md)。真实登录由本人在浏览器完成；不自动调用模型消耗额度。

采用既有方案进行 P0 验证，认证路线和平台放行仍以真实证据为准。用户已选择 Style ID=hashicorp，根 AGENTS 已记录。未实现的产品规则仍按决策表跟踪；发布另设确认点。

实施以可独立验收的纵向切片推进。每项先编写失败行为测试，再实现最小代码、回归并更新文档。原生 UI/系统集成无法完全自动化的部分必须保留实机证据。

## P0：回答最可能推翻方案的问题

目标：确认登录/模型路线与 GPUI Windows 组合值得继续投入。

| 任务 | 输出与验证 |
|---|---|
| P0.1 | 核对当前官方认证、模型和工具限制，锁定候选版本与资料日期 |
| P0.2 | 干净应用状态下 Codex 设备码授权；只由用户在浏览器完成登录；记录身份/调用权限的脱敏结果 |
| P0.3 | 模型列表、一次真实 completed 文本、Codex 平铺函数调用与结果回传；验证 Chat 可见历史往返 |
| P0.4 | 查明实际 Trae 版本默认字段与流内错误行为，列出可支持配置或具体阻塞 |
| P0.5 | 最小 GPUI/Kit 窗口验证 IME、DPI、托盘、浏览器打开、Tokio 状态桥接；锁定匹配依赖 |
| P0.6 | 在干净 Windows 环境运行最小可执行文件，记录原生依赖、最低系统候选与资源基线 |

验收：A01 的真实认证链、A13/A21 的最小协议验证、A29 的最小平台验证。证据必须是实际运行，不能用文档代替。

停止/变更条件：账号无资格、目标模型不提供、工具语义无法满足、GPUI 关键系统能力不可用。输出实测报告后由用户决定调整认证或范围；不自行切回 SIWC、API Key 或其他 UI 框架；Codex 路线已由用户明确批准。

人工确认：P0 前批准认证试验方向；P0 后确认最终认证、平台与必要兼容取舍。

## P1：工程骨架与本地安全基础

目标：可运行的空桌面壳、可靠的后台生命周期和可测试存储。

- 创建单 package、模块目录、格式/lint/测试配置、Windows CI 与锁文件。
- 建立 AppCommand/AppSnapshot、Tokio 所有权、单实例和明确退出。
- 实现 SQLite 迁移、配置、注册元数据、Windows 凭据保护、密钥摘要存储。
- 创建 fake 上游和真实 socket 测试工具；样本仅合成或脱敏。
- 验证数据库失败、DPAPI 失败、重复启动、状态通知和任务回收。
- 2026-10-13 数据恢复修复：默认存储移至不受 AppData 重定向影响的用户目录；一致性复制旧库并保留原文件，拒绝来源冲突，覆盖 A40/A41。运行证据见开发验证记录。

测试先行：A07/A28/A31/A34 的基础场景。验收：空应用启动/退出、数据库迁移、凭据不明文、CI 的 fmt/clippy/test/build 有证据。

人工确认：先确认隐私/删除/安全默认值；正式视觉壳之前选择本地 Style ID 并记录到 AGENTS。

## P2：从零登录到桌面模型测试

目标：用户无需 Codex，从界面建立连接并完成一条真实推理。

- 登录向导、临时回调、身份校验、权限状态、受保护保存。
- 刷新单飞、Token 轮换、错误分类、重新登录和退出。
- 保存本人多个注册但只激活一个；模型目录按注册隔离。
- 桌面模型测试入口，真实完成和错误结果都能显示。
- 模型测试使用后续共用的传输/终态模块，不写另一份临时生产协议。

验收：A01—A08、A10；包括 16 并发刷新 fake 测试和真实账号最小推理。此时仅桌面内测试，不对局域网开放。

## P3：Chat Completions 的完整纵向链路

目标：在本机用 Trae/测试客户端完成文本及工具调用往返。

- 建立 /v1/models、/v1/chat/completions 和网关密钥鉴权。
- 严格字段校验、messages/tools/history 映射、Codex 平铺函数工具适配。
- 2026-10-13 reasoning_content 报错修复切片：按 [Chat 推理历史契约](../03-architecture/api-contracts.md#chat-推理历史兼容规则) 接收 assistant 元数据并提示未回放，覆盖 A17e/A17f；真实 Agent 重试仍需记录。
- 2026-10-13 index 与同类客户端兼容切片：只读对照 cursor-byok-main/codex-proxy-dev，先复现，再实现已知元数据及 null 规范化；覆盖流式工具聚合后回传结果、JSON/SSE 四种组合和严格拒绝边界 A17g/A17h。同步验证 P4 的函数工具可选字段、推理配置空值和合法回放状态；真实客户端重试仍单独验收。
- 完整 SSE 帧解析和 Responses 终态，Chat 流式/非流式编码。
- 交错工具增量、拒绝内容、usage、错误和不支持参数。
- 下游断开、非流式取消、背压、并发/大小/时间预算。
- 接入固定版本 Trae，形成实际兼容矩阵与配置说明。
- 2026-10-13 用户批准第三方 Agent 长度参数兼容切片：按 [API 契约](../03-architecture/api-contracts.md#输出长度参数兼容规则) 接收并移除 Codex 不支持的长度上限，添加响应头提示，覆盖 A17a/A17b；真实 Agent 文本和工具验收仍单独执行。

验收：A09、A11—A19、A21—A23；真实文本及工具往返不可省略。任何自动丢弃参数或推理回放扩展都必须先记录取舍并评审。

## P4：Responses 原生子集

目标：为 Responses 客户端提供尽量保留原生语义的接口。

- /v1/responses 输入校验、完整历史与工具关联。
- 保留支持范围内的原始事件、ID、索引、reasoning 回放项。
- stream=false 聚合真实终态对象。
- 明确拒绝 previous_response_id、服务器会话、托管工具和未支持输入。
- 使用固定 SDK 验证字段与异常，不通过降为 Chat 后重建原生输出。
- 2026-10-13 用户批准图片兼容切片：按 [图片输入契约](../03-architecture/api-contracts.md#图片输入兼容规则) 补齐 Chat/Responses 用户 Base64 图片，先复现拒绝再实现，覆盖 A17c/A17d；真实 Codex 图片和客户端重试另行记录。

验收：A14—A20 及 Responses SDK 契约；文档能力表与实现逐项一致。

## P5：个人跨设备与桌面操作闭环

目标：用户可完成日常启停、配置和跨设备使用。

- 具体 LAN/VPN 网卡选择、端口、连通性状态、地址复制。
- 按客户端命名密钥、DPAPI 保存及查看/复制、撤销及在途取消；2026-10-13 根据 [B20](../01-requirements/business-rules.md) 改为撤销即删除、不再展示及清理历史已撤销记录，覆盖 A45—A47。
- 概览、连接、模型、接入、请求记录、设置页面。
- 托盘、关闭窗口、恢复、显式退出、可选登录后自启。
- 脱敏请求元数据、筛选、保留策略、清理和诊断导出。
- 第二台本人设备分别从 LAN 与个人 VPN 发起请求。

验收：A24—A30、A34；本机 curl 不能替代 A26。连接操作不自动修改系统防火墙、代理或证书。

## P6：安装包、稳定性与完成前验证

目标：形成可交付的个人使用版本与真实验证记录。

- 打包 Windows x64 安装包，核对原生运行资源、许可与依赖。
- 干净机完成零登录、文本、工具、跨设备、托盘与退出流程。
- 执行 4 并发、慢消费者、随机断流、睡眠恢复和 30 分钟资源测试。
- 验证 SQLite 升级/恢复、密钥撤销、诊断脱敏与不支持字段。
- 按 A01—A34 汇总自动与人工证据，修复问题并补回归测试。
- 更新 README 启动/安装说明、兼容矩阵、已知限制与发布说明。

验收：质量计划的相关检查通过、核心流程无阻塞失败、没有秘密信息进入工件。正式签名、对外分发和发布由用户另行确认。

## 变更与完成定义

新增能力先修改 PRD、API、威胁模型和验收，再进入对应阶段。实际测试失败不通过删除断言、扩大 mock 或降低标准处理。

某阶段完成需同时具备可演示行为、相关检查、文档一致性和已知限制；“能编译”“登录成功”或“模型返回过一段文字”均不能单独代表项目完成。
