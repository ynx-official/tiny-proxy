## 首次使用

1. 欢迎页说明本应用向自己的 Agent 提供模型接口，展示“Continue with ChatGPT”登录入口。
2. 点击后先创建本地回调监听，再打开系统浏览器。桌面显示“等待浏览器授权”、重新打开浏览器和取消按钮。
3. 授权完成后显示账号标签、权限状态；仅有身份登录权限时明确显示“尚未允许模型调用”。
4. 自动同步模型目录；用户主动点击“测试连接”，说明会发起一次真实模型请求并消耗对应使用额度。
5. 测试成功后进入接入向导：选择本机或指定 LAN/VPN 地址，设置端口，创建命名网关密钥。
6. 新密钥加密保存，默认只显示名称和前缀，可随时查看或复制；明文展示两分钟后隐藏。旧摘要密钥无法还原。
7. 启动成功才展示可复制的连接地址、完整 Chat URL 和模型 ID，并给出 Trae 配置说明。
8. 跨设备访问失败时，引导检查网卡、VPN 与防火墙；不自动改系统网络设置。

用户不需要安装 Codex、输入账号密码到本应用、复制上游 Token 或编辑配置文件。

## 页面与职责

| 页面 | 主要内容 | 主要操作 |
|---|---|---|
| 概览 | 当前活动连接、服务状态、监听地址、并发数、最近错误 | 启停、连接测试、进入接入向导 |
| 账号连接 | 已保存的本人注册、调用权限、到期/续期状态 | 添加、切换、重新登录、退出 |
| 模型 | 当前目录、刷新时间、能力与验证状态 | 刷新、选择测试模型、复制 ID |
| 客户端接入 | 地址、端口、Base URL/完整 URL、命名密钥 | 创建/撤销密钥、复制连接信息 |
| 请求记录 | 起止时间、模型、密钥/账号 ID、状态、阶段、首个输出、上游活动、使用量 | 请求/失败异常独立页签、每页 100 条、查看关联元数据详情、复制请求 ID；自动按保留周期清理，详见 [请求诊断](../05-operations/request-diagnostics.md) |
| 设置 | 外观主题、启动行为、托盘、限制、保留时间、关于 | 选择跟随电脑/白天/夜间主题；其他设置按实施状态交付 |

不提供终端、项目文件树、会话编辑器、Agent 任务面板或工具审批页。请求记录不是对话历史。

主题选择的即时保存、失败反馈与系统变化规则见 [桌面视觉系统](visual-system.md#白天模式与跟随电脑)，实现及未验证项见 [主题清单](../04-quality/theme-checklist.md)。

## 状态展示

认证、网关和单次请求分别建模，禁止一个“已连接”灯代表全部状态：

- 认证：未连接、等待授权、已登录但无调用权限、可调用、续期中、需重新登录、暂时不可达。
- 网关：停止、启动中、监听中、停止中、失败。
- 请求：等待上游、接收中、完成、受限结束、失败、取消。
- 模型：未同步、同步中、已缓存、当前权限待复核、同步失败。

网关监听正常但上游断网时，应显示“服务运行中 / 上游不可达”，避免错误引导用户修改端口。

## 生命周期与异常

| 情况 | 桌面结果 |
|---|---|
| 浏览器未能打开 | 保留本次尝试，提供再次打开；不打印含登录提示 Token 的完整 URL |
| 授权取消或超时 | 保持原活动账号，销毁本次回调状态，可重新开始 |
| 端口冲突 | 提供修改端口或重试，客户端地址未确认前不换端口 |
| 网卡地址消失 | 停止该监听并提示；不回退到所有网卡 |
| 切换活动账号 | 仅影响新请求，模型目录随之切换；在途请求保持原连接 |
| 退出账号 | 确认受影响请求数，停止其请求，处理远端撤销并清除本地 Token |
| 关闭窗口 | 若托盘已可用则收起并首次提示；托盘不可用时不能留下无法控制的后台进程 |
| 托盘“退出” | 结束监听、处理在途请求、保存必要配置并结束进程 |
| 重复打开应用 | 唤起已有实例，不产生第二个刷新凭据或监听的进程 |
| 系统休眠恢复 | 原流报中断；重建连接池、检查网卡/凭据；不重放生成请求 |

## UI 风格

已创建全页面 ASCII 低保真原型，用户于 2026-10-13 选择 Style ID=hashicorp。已读取本地 DESIGN.md 并记录到根 AGENTS；[视觉系统](visual-system.md)说明原生桌面适配。GPUI 使用主题变量，不引入 Vue、WebView 或 CSS 构建。

候选来自本地 style-index：

| Style ID | 适用点 | 取舍 |
|---|---|---|
| hashicorp | 配置、连接、权限状态清楚 | 风格偏严谨 |
| sentry | 错误与运行状态辨识强 | 技术信息密度较高 |
| airtable | 初次使用与表单易理解 | 比较柔和 |

上表保留候选选择依据，当前仅采用 hashicorp。功能流程不以某个风格为前提。
