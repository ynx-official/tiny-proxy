## 代码验证范围

先补充 tests/theme_preferences.rs，再实现主题偏好、后台命令与迁移。覆盖默认跟随、固定选择、存储值校验、新库默认值、旧库升级保留状态、三种偏好重启、数据库约束、后台保存回执及写入失败保留原选择。src/desktop/theme.rs 包含普通/高透明度系统外观映射及两套配色的正文、状态、按钮和焦点对比度断言。

按项目限制未执行编译、cargo test、clippy、build、run 或打包；这些是测试代码，不能据此宣称运行通过。当前旧程序不会自动应用源码改动。源码格式和差异检查的实际结果集中在开发验证记录。

## 用户授权测试后建议执行

```powershell
cargo test --locked --test theme_preferences
cargo test --locked --bin tiny-proxy desktop::theme::tests
```

第二条验证桌面主题的纯逻辑和配色，不会打开窗口；仍会编译，仅在明确授权后运行。后台测试使用临时数据库、合成数据，不需要真实账号或模型调用。

## 桌面实机检查

1. 新数据目录及从旧库升级时，分别在 Windows 浅色/深色应用模式启动，核对默认选中“跟随电脑”、所有页面和输入框颜色；升级不丢账号、监听与历史。
2. 运行期间切换 Windows 的默认应用模式，跟随模式应同步；分别选择固定白天/夜间再切换电脑外观，应用内容应保持固定模式。
3. 每种偏好关闭再打开，确认恢复选择；从固定模式切回跟随，立即使用电脑当前外观。
4. 保存期间按钮禁用；注入数据库写入失败或后台队列不可用，确认提示且保留原选择，可再次重试。
5. 在两种主题下遍历概览、账号、模型、客户端接入、请求/异常详情与设置；检查按钮 hover/active/disabled、Tab 焦点、输入/占位符、错误提示、滚动条、100%/150%/200% DPI 及小窗口。
6. 网关运行和请求进行中切换主题，确认监听地址、账号与在途请求不受影响；只在另行批准真实调用时检查真实账号链路。

上述实机场景尚未执行。视觉与系统通知不能由源码格式检查替代。
