## 本次交付与限制

用户要求自定义端口以避开占用。已修改独立 IP/端口输入、共用启停命令、恢复回填及占用错误提示，沿用既有 SQLite 监听配置。先补回归代码再修改实现；按根 AGENTS 默认限制未运行失败基线、Rust 测试、编译、Clippy、应用或打包，未停止或替换已有程序。

## 回归代码与建议命令（未运行）

- `desktop::presentation::tests`：单独修改端口保留本机/LAN/VPN/IPv6 IP；1/65535 边界与默认值；0、越界、负数、小数、文字、内部空格及非 ASCII 数字拒绝；原网络边界保留；旧监听配置拆分和损坏值保留；输入无效仍能停止服务。
- `tests/gateway_startup.rs`：原端口持续被占用时启动失败且保留配置，改用其他端口成功监听及保存，新的 URL 返回网关鉴权结果；原端口仍被占用时重开恢复新端口和界面配置，退出释放端口。保留原失败尝试不覆盖配置、连续启停及自动启动用例。

仅在用户授权相关测试后执行：

```powershell
cargo test --locked --bin tiny-proxy desktop::presentation::tests
cargo test --locked --test gateway_startup
```

使用临时 SQLite 与本地 fixture，无需真实账号或模型调用。

## 桌面检查（全部待验）

1. 在“客户端接入 → 连接地址”检查监听 IP 和端口分别回填，白天/夜间、960×640 与高 DPI 下标签/输入/按钮不重叠，可用 Tab 和粘贴编辑端口。
2. 服务运行时两项禁用且显示停止后可修改；点击停止并收到回执后，只改端口为可用值，分别从接入页和概览启动，确认实际监听、三种连接 URL 与复制值包含新端口。
3. 使用另一进程占用原端口，启动失败提示具体端口和修改入口；保持占用进程运行，修改端口后重试成功。地址不存在等其他错误仍显示实际原因。
4. 非法端口显示范围错误，不发起启动或进入等待；清空 IP/端口分别使用默认值。服务启停等待时输入禁用，连点不重复提交。
5. 成功修改后正常退出并重开，IP、自定义端口及自动监听一致；失败的新配置不替代上次成功值。旧库配置可恢复，不修改账号、密钥或请求数据。
6. 把新 Base URL 更新到外部客户端，再执行客户端连接检查；涉及真实模型调用需本人另行授权。未启动时仍不能复制未生效的地址。
