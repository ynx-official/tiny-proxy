## 版本概述

修复下游客户端带扩展字段时被本地严格校验拒绝的问题，按用户明确要求默认信任请求字段。提供必要转换错误的具体路径与修正建议，改善请求详情的异常关联与短耗时显示。发布 Windows x64 和 macOS arm64，各有安装版与便携版。

## 请求兼容与转换

- 取消顶层及嵌套字段白名单；未知/用不到的顶层选项跳过，Chat 扩展元数据不进入提示词，Responses 原生输入及函数定义扩展保留给上游判断。
- 长度字段、temperature 等采样选项任意值兼容接收后跳过；已知未生效字段使用固定响应头提示。上游仍 stream=true、store=false，返回一个结果，不模拟输出上限。
- 放松 reasoning_content、工具 index/name、函数名称/数量/schema/参数 JSON/历史配对及原生状态枚举校验；保留历史顺序和实际调用 ID/参数，不执行工具。Chat 参数字符串原样保留，其他类型序列化为 JSON 字符串。
- stream/include_usage/parallel_tool_calls 接受常见字符串或数字布尔值；推理选项不因本地模型目录未声明该枚举而直接拒绝。
- 接收 Chat 图片的包装对象/直接 Base64 字符串及 input_image 形式，忽略扩展元数据，detail 缺省/null 为 auto，其他值交给上游。既有 user Base64 入口和不抓取 URL/读取路径规则保持。
- 保留 JSON、必要消息/输入结构、调用 ID/名称和图片转换要求；账号、模型目录、网关鉴权、固定上游和终态/取消检查保持。缓存原值在 JSON 中，仅能安全编码为 HeaderValue 的值用于请求头。

## 行为与界面变化

未知字段和可选参数不再直接造成 unsupported_or_invalid_parameter 的本地 400；上游不支持的原生值仍可能被真实上游拒绝。无法转换的必要结构返回具体 error.param 路径与固定安全建议，日志不包含请求值或任意扩展字段名称。

请求详情按请求 ID 独立读取异常，异常不在当前分页时仍能展示/复制；切换或收起后忽略旧详情响应。小于 10 毫秒的耗时与延迟显示毫秒，例如 5 毫秒，不再舍入成 0.00 秒。Windows 托盘与显式退出行为沿用 v1.1.0。

## 配置与数据兼容性

无新设置、表或数据库迁移，继续使用迁移 0001–0008。数据目录、凭据保护、账号/密钥和元数据保留策略保持；旧通用异常不补写或推断字段。源码、界面和平台资源版本由 Cargo.toml 的 1.1.1 统一生成。

此前严格校验契约已保留历史快照；当前 API 文档及验收场景同步默认信任规则。回退旧版本仍可能重新拒绝这些扩展请求，但本版没有增加数据库回退障碍。

## 升级说明

从 v1.1.0 升级前保留一致性数据备份，并从托盘或设置完全退出旧程序。应用内下载/安装仍需手动确认；Windows/macOS 选择对应平台的安装包或便携包并沿用原数据目录。本次发布操作不自动停止、安装或替换正在使用的应用。

## 破坏性变更与已知问题

- 未用到的客户端参数被跳过，不代表对应采样、长度、会话或多结果语义已经实现；已知字段的未生效提示可能影响依赖原严格 400 的客户端。
- 原生值默认由上游判断；本地接收不保证真实 Codex 支持，必要转换错误和上游拒绝仍可能失败。
- 本版按用户要求跳过 Rust/Python 测试，真实客户端、原生窗口、安装与更新往返尚未实测；编译/打包不能替代这些验收。
- 代码签名/公证、macOS 托盘和远端账号撤销等限制沿用前版。
